# Deploying GoAhead Securely

GoAhead ships set up for evaluation and testing, not for service. Before a device carrying GoAhead is put in front of users, work through this list.

Settings named `ME_GOAHEAD_*` are build-time defines, documented where they are declared in `src/goahead.h`. Override one with `-D` when building, or in your own project files. The makefiles do not track compiler flags, so a changed define only takes effect in a clean build: `make clean` followed by, for example, `make CFLAGS=-DME_GOAHEAD_CASE_INSENSITIVE_FS=1`. Start the server with `--verbose` to confirm strict mode: it logs whether strict mode is on. Command-line options are described in `doc/man/goahead.txt`.

## Building

- **Build the release configuration for production.** A plain `make` builds the debug configuration, which is unoptimized and carries assertions and debug tracing. Build what you ship with `make clean` followed by `make OPTIMIZE=release` (in Visual Studio, the Release configuration). The release build is optimized and stripped and, on Linux, macOS and FreeBSD, compiled with `_FORTIFY_SOURCE=3`.
- **If you compile GoAhead with your own build, apply the same hardening.** The GoAhead project files and `make` compile with the flags below. Compiling `dist/goaheadLib.c` or the files in `src/` with your own toolchain applies none of them, and running `make -C projects/gmake2` directly applies all but the control-flow protection, which the top-level `make` selects for the compiler. With GCC or Clang, compile with `-O2 -D_FORTIFY_SOURCE=3` (fortification needs optimization), `-fstack-protector-strong`, `-fcf-protection=full` on x86-64 or `-mbranch-protection=standard` on Arm64, and `-Wformat=2 -Werror=format-security`; build executables with `-fPIE` and link them with `-pie`, build the shared library with `-fPIC`, and on Linux and FreeBSD link with `-Wl,-z,relro,-z,now -Wl,-z,noexecstack`. With MSVC, compile and link with `/guard:cf`, and link with `/DYNAMICBASE /HIGHENTROPYVA /NXCOMPAT /CETCOMPAT`.
- **Check the hardening of an ELF build.** `readelf -lW` must show a `GNU_RELRO` segment and a `GNU_STACK` segment without the `E` flag, `readelf -d` must show `BIND_NOW`, `readelf -h` must show type `DYN` for an executable built as PIE, and `nm -D` must list `__stack_chk_fail` and fortified `__*_chk` functions such as `__snprintf_chk`.
- **Build the library and the application with the same settings.** `goahead.h` sizes structures and selects features from the `ME_GOAHEAD_*` defines, so an application that embeds GoAhead must be compiled with the same defines as the library, or the two disagree about them.
- **Provision enough stack.** GoAhead handles every request on the stack of the task or thread that calls `websServiceEvents`, and nothing guards against overflowing it. On an RTOS or a no-MMU target such as uClinux, where a task stack is a few KiB and has no guard page, an overflow corrupts memory silently. Give that task at least 16 KiB, plus 0.3 KiB for each level of `ME_GOAHEAD_LIMIT_SCRIPT_RECURSE` when `ME_GOAHEAD_JAVASCRIPT` is on, which is 48 KiB with the default limit of 100. These figures are twice what a 64-bit Linux build needed in testing. Lower `ME_GOAHEAD_LIMIT_SCRIPT_RECURSE` to fit a smaller stack, and measure on your target. The libraries and compiler you build with can use larger frames, and your own action functions and JavaScript functions run on the same stack.

## Logging

- **Size and protect the log partition.** The error log (`--log`) and the access log are appended to across restarts, created mode 0640 and never opened through a symbolic link. If a log cannot be opened, GoAhead reports it and refuses to start. Each log is renamed to `path.old` when it reaches `ME_GOAHEAD_LIMIT_LOG_SIZE` (default 1 MB; 0 disables rotation), so allow twice that per log on the device. Standard output and standard error are not limited. Requests a client can send without authenticating are traced at level 2 or above and never at the default level, so they cannot grow the log of a server running at level 0.
- **Authentication failures are logged at level 0.** Each failed Basic, Digest or form authentication, each request refused for lacking an ability or coming from another site, and each form login and logout writes one line naming the user, the client address, the route and the scheme. A Basic or Digest success, which recurs on every request, is logged at level 2. Watch for repeated failures: GoAhead does not rate limit them. A build with `ME_GOAHEAD_LOGGING=0` has no log and records none of this; `ME_GOAHEAD_TRACING=0` keeps it.
- **Debug builds log credentials.** Release builds redact the `Authorization`, `Proxy-Authorization`, `Cookie` and `Set-Cookie` values, the query string of the request line and multipart form field values from trace output at every level. Debug builds log them in full, so never run a debug build on real traffic or with real credentials.

## Routes and authentication

- **Replace the sample route file.** `src/route.txt` serves the whole document directory to anyone. Write routes for your content and require authentication (`auth=`) and abilities (`abilities=`) on everything that is not public. Routes are matched in order, so put protected routes before the action, template and CGI routes and before any broader route that covers the same directory, as the Authentication section of `src/route.txt` shows. A login gate for the whole site, `uri=/`, should use `handler=continue`, so the request goes on to the route that serves it and a template is run rather than served as source. A gate's `dir=` changes nothing, because a gate serves nothing; and a gate with `methods=`, `protocol=` or `extensions=` authenticates only the requests those match, so do not put an unauthenticated route under it that accepts others (the server refuses such a table). A route that protects one directory should serve it from its own `dir=`, outside the documents directory, so a request spelled to miss the route, by letter case or a Unicode fold, finds nothing to serve at the broader routes after it. When `ME_GOAHEAD_CASE_INSENSITIVE_FS` is set, the default on Windows and macOS, a request path holding a non-ASCII letter that the file system folds to ASCII, such as U+017F for "s", is refused with 400.
- **Do not start an unsafe route table.** At startup GoAhead refuses a route table in which an unauthenticated route before or after a protected route can serve its requests, or an action, template or CGI route comes before an authenticated route that covers it. It warns about a table with no authenticated route but starts it. `--no-strict`, or a build with `ME_GOAHEAD_STRICT=0`, turns the refusals into warnings; do not ship either. The table is checked once, at the first `websListen`, after the route and auth files are loaded: an application must add its routes before then.
- **Match the build to the document storage.** Routes are matched to request paths with the letter-case rule of `ME_GOAHEAD_CASE_INSENSITIVE_FS`, which is set by default only on Windows and macOS. A document or route directory on FAT, exFAT, SMB/CIFS, a case-insensitive ext4 directory or another file system that ignores case needs `ME_GOAHEAD_CASE_INSENSITIVE_FS=1`, or a case variant of a protected path, such as `/AUTH/` for `/auth/`, misses its route and the same file is served by a broader one. A build with it at 0 checks each served directory at startup and treats one whose file system ignores case as an unsafe route table.
- **Accept uploads only where you mean to.** A multipart upload is parsed only on a route with `upload=true`, after that route's authentication. Other routes refuse uploads with 415, except CGI routes, which pass the body to the program. Put every upload route behind authentication: give it `auth=`, or place it after a login gate that covers it. An upload request may hold at most `ME_GOAHEAD_LIMIT_UPLOAD_FILES` files (default 16) and `ME_GOAHEAD_LIMIT_PARAMS` parts (default 512); raise them at build time only as far as your forms need.
- **Protect an action by naming it in its own route.** An action runs only through a route whose prefix names it, such as `route uri=/action/upload auth=form ... handler=action`, or, when no route names it, through any action route that names no action, such as `/action`. An authenticated route that names no action beside a public one protects nothing, and GoAhead refuses that table at startup.
- **Keep actions on POST.** Actions run for POST only unless their route names its methods, because any page a user visits can make the browser send a GET with the session cookie. Allow GET only for actions that change nothing. The login action reads the username and password from the request body only. Any request other than GET or HEAD, on every route, is refused with 403 when its `Origin` header names another site, or, when `Origin` is absent, its `Sec-Fetch-Site` header does, since a browser sends its cookies, cached Basic and Digest credentials and client certificate with a form another site submits. A route that must accept a form post from another site, such as an identity provider callback, can opt out with `cross-site=allow`; on a login route that removes login CSRF protection. Behind a reverse proxy, see "Behind a reverse proxy" below.
- **Never deploy the sample or test user files.** `src/auth.txt` holds only commented examples, and `test/auth.txt` holds test accounts whose passwords are published. Create your own users and passwords with `gopass`.
- **Protect the password file.** Keep `auth.txt` outside the documents directory, owned by the server account and readable by no other account (mode 0600). An MD5 hash, which Digest authentication requires, is a password equivalent: anyone who reads it can authenticate with Digest without knowing the password. Prefer Blowfish hashes, the `gopass` default, with form authentication. Run `gopass` without `--password` so it prompts for the password, which keeps it out of the process list and the shell history.
- **Change the realm.** `ME_GOAHEAD_REALM` defaults to `example.com`. The realm is part of every stored password hash, so set your own and then create the passwords with `gopass` using it.
- **Prefer form authentication over HTTPS.** Basic authentication sends the password with every request and Digest depends on MD5. Both are supported for compatibility only. Whatever the method, serve it only over HTTPS: use `protocol=https` on the route, or redirect HTTP to HTTPS as shown in `src/route.txt`. A build without TLS warns at startup for every route that uses authentication, since its credentials and session cookies cross the network unencrypted.
- **Size the session table.** Each account may hold `ME_GOAHEAD_LIMIT_SESSION_USER` sessions (default 8); a further login retires its least recently used one, so one account cannot fill the table. Set `ME_GOAHEAD_LIMIT_SESSION_COUNT` to at least the number of accounts times that limit. A handler on a public route that calls `websSetSessionVar` creates a session for each anonymous client, which the per-account limit does not cover.
- **Sessions expire when idle.** A session expires after `ME_GOAHEAD_LIMIT_SESSION_LIFE` seconds without a request (default 1800, 30 minutes). The session cookie is always `HttpOnly` and `SameSite=Lax`, and is marked `Secure` only on a request that arrived over HTTPS, so serve the login and every authenticated page over HTTPS only.

## TLS

- **Use a supported TLS library and keep it patched.** GoAhead requires OpenSSL 3.0 or later, or MbedTLS 3.6.7 or later, and refuses to compile against anything older. That is the oldest the code accepts, not a recommendation: link against a release series its maintainers still support with security fixes, such as OpenSSL 3.5 LTS or the latest MbedTLS 3.6 LTS release, or a build your operating system vendor maintains. GoAhead does not ship or pin either library, so track its advisories and record the version you link in your own SBOM.
- **Supply your own certificate and key.** An `https://` endpoint needs them, given with `--cert` and `--key` or built in with `ME_GOAHEAD_SSL_CERTIFICATE` and `ME_GOAHEAD_SSL_KEY`. Without them GoAhead refuses to listen on the endpoint. The key must be an unencrypted PEM file, protected by file permissions: GoAhead never prompts for a passphrase, and an encrypted key, or a key that does not match the certificate, stops startup.
- **Require HTTPS.** Build with `ME_GOAHEAD_SECURE_ONLY=1`, which needs a TLS build, to redirect every plain HTTP request to HTTPS before any route is consulted. When a front-end terminates TLS for you, declare it as a trusted proxy (see "Behind a reverse proxy") so this redirect, HSTS and the session cookie follow the scheme the client used. Set `ME_GOAHEAD_HSTS`, for example to `max-age=31536000`, so browsers keep using HTTPS.
- **Protocol versions.** By default GoAhead offers TLS 1.3 only (`ME_GOAHEAD_SSL_NO_V1_2` is 1), and never TLS 1.1 or earlier. Set `ME_GOAHEAD_SSL_NO_V1_2` to 0 only if you must serve TLS 1.2 clients, and then set `ME_GOAHEAD_SSL_CIPHERS` to forward secret AEAD suites, such as the ECDHE AES-GCM suites, unless your clients need the AES-CBC suites the default list also enables for TLS 1.2.
- **Ciphers.** Both TLS libraries share one default list: the TLS 1.3 suites and, when TLS 1.2 is enabled, forward secret ECDHE suites with AES-GCM or AES-CBC-SHA2. A list given in `ME_GOAHEAD_SSL_CIPHERS` never enables static RSA, anonymous, null, export, DES, 3DES, RC4 or MD5 suites for TLS 1.2, and a list with no usable suite stops startup.
- **Do not use test certificates.** The certificates and keys the test suite generates are for testing. Create a key and certificate for your product and keep the key private.
- **Client certificates.** With `ME_GOAHEAD_SSL_VERIFY_PEER` on, clients must present a certificate. Unless you also set `ME_GOAHEAD_SSL_VERIFY_ISSUER`, any certificate is accepted, whether self-signed, from an unknown issuer, or naming your CA as issuer without being signed by it; it proves only that the client holds its key, and does not authenticate the client. `ME_GOAHEAD_SSL_AUTHORITY` and `ME_GOAHEAD_SSL_REVOKE` take effect only with `ME_GOAHEAD_SSL_VERIFY_ISSUER`, and GoAhead warns at startup when they are set without it. Set it and `ME_GOAHEAD_SSL_AUTHORITY` if client certificates are how you authenticate. Client certificates are verified only against that authority, never the system's CA store; with issuer verification on and no authority, every client is refused. If you set `ME_GOAHEAD_SSL_REVOKE`, the file must hold a CRL from every CA in a client's chain: a chain through a CA with no CRL in the file is refused on both TLS libraries. A browser presents its certificate with a form another site submits too, so the cross-site refusal under "Keep actions on POST" applies to these routes as to any other.

## Network exposure

- **Listen only where you must.** `ME_GOAHEAD_LISTEN` defaults to `http://*:80,https://*:443`, every interface. Name the addresses to listen on, on the command line or in that setting.
- **Run with the least privilege.** Start GoAhead as an unprivileged account where you can, using ports above 1024 or granting only the right to bind low ports (for example the Linux `CAP_NET_BIND_SERVICE` capability). If it must start as root, give `--user` and `--group`, or build with `ME_GOAHEAD_USER` and `ME_GOAHEAD_GROUP`: GoAhead changes to that account after it listens and opens its log, certificate, route and authentication files, and exits if it cannot. Applications embedding GoAhead call `websDropPrivileges` at the same point. The `goahead` program warns at startup when it is left running as root; an application embedding GoAhead gets no such warning and must make that check itself. The account needs read access to the documents and write access only to the upload and PUT directories and to `auth.txt` if users are edited at runtime.
- **Put a firewall or proxy in front of untrusted networks.** GoAhead is single threaded. It limits connections in total (`ME_GOAHEAD_LIMIT_CONNECTIONS`) and per client address (`ME_GOAHEAD_LIMIT_CONNECTIONS_PER_IP`), and bounds request sizes and times with the other `ME_GOAHEAD_LIMIT_*` settings. It does not limit request rates. A trusted proxy is exempt from the per-address limit, which cannot see the clients behind it, so limit clients at the proxy.
- **Behind a reverse proxy.** List the proxy's address with `--proxy` or `ME_GOAHEAD_TRUSTED_PROXIES` (or `websSetTrustedProxies`). GoAhead then takes the client's scheme from the right-most `X-Forwarded-Proto` value of requests from that address, for the session cookie's `secure` attribute, HSTS, redirects, `protocol=` routes and the cross-site check, and ignores forwarded headers from anyone else. The proxy must overwrite, not append to, `X-Forwarded-Proto`, must preserve `Host` or you must call `websSetHostUrl` with the public host, and must not strip `Origin`. Make the backend reachable only through the proxy. `X-Forwarded-Host` and `X-Forwarded-For` are not used.
- **Bound slow clients on stacks without send timeouts.** GoAhead limits how long it waits for a client to accept a response with the socket send timeout (`SO_SNDTIMEO`). Some network stacks, such as older VxWorks releases, do not support it: there a client that stops reading can stall the server, and GoAhead logs a warning when it detects this. On such a device, put a proxy that buffers responses in front of it.
- **Never run with `--debugger`.** It disables every request and session timeout.
- **Service managers may close stdio.** On POSIX, `websOpen` opens descriptors 0-2 on `/dev/null` when they are closed, so log output meant for stderr cannot reach a client connection or a staged file. An application that opens files or sockets before `websOpen` with stdio closed must reserve those descriptors itself first.
- **SIGPIPE.** On POSIX, `websOpen` ignores SIGPIPE when it is at its default, so a client that disconnects mid-response cannot kill an application that embeds GoAhead. An application that wants the signal installs its own handler before `websOpen`, and must then handle broken connections itself.
- **Memory exhaustion aborts.** GoAhead does not check allocation results: a failed allocation calls the notifier set with `websSetMemNotifier` and then aborts the process, even if the notifier returns. Use the notifier to log, and rely on a supervisor to restart the server.
- **Disable core dumps.** A core file holds the server's memory, including private keys, passwords and session data. GoAhead does not change the core size limit, so set it to zero where the server is started: `LimitCORE=0` in a systemd unit, or `ulimit -c 0` in a start script.

## Content and features

- **Turn off what you do not use.** CGI, JavaScript templates, uploads and Digest authentication are on by default: set `ME_GOAHEAD_CGI`, `ME_GOAHEAD_JAVASCRIPT`, `ME_GOAHEAD_UPLOAD` or `ME_GOAHEAD_DIGEST` to 0 to remove them. A build with `ME_GOAHEAD_JAVASCRIPT=0` has no template handler, so remove the template route (`handler=jst`) from the route file, which is otherwise refused; template files left in the documents are refused with 404, not served. A build with `ME_GOAHEAD_AUTH=0` cannot authenticate and serves every route to anonymous clients, so every route must be safe for anonymous use: it refuses a route file that asks for authentication, but strict mode has no protected route to check and the server only warns at startup.
- **Keep the document directory to what you mean to serve.** Hidden files (names beginning with `.`, except `/.well-known/`) and backup, swap and temporary copies, whether files or directories (any path segment ending in `~`, `.bak`, `.orig`, `.swp` or `.tmp`), are refused by default (`ME_GOAHEAD_DENY_HIDDEN`), but everything else in it can be requested. Do not keep source files, configuration or version control directories there.
- **Do not let untrusted accounts create links in the document directory.** On Linux, macOS, FreeBSD and other Unix-like systems, GoAhead refuses a request whose file resolves, through a symbolic link, outside the document directory (`ME_GOAHEAD_CONTAIN_DOCUMENTS`, on by default). Other platforms, including Windows and VxWorks, do not make this check: a link or Windows junction inside the document directory is followed for GET, PUT and DELETE. On those platforms, make sure only trusted accounts can create entries in the document directory, the PUT directory and their parents.
- **On Windows, restrict who can write to the application, CGI and document directories.** The `goahead` program limits DLL loading to the Windows system directory and the application directory, and removes the working directory from the search order. An embedding application should call `websHardenProcess()` first thing in `main` to get the same protection. The application directory is still searched, so keep it, every CGI directory and the document directory writable only by trusted accounts. Each CGI program starts in its route's directory and loads its own libraries under its own search rules.
- **Treat CGI programs as part of the server.** They run with the server's own account and privileges. A CGI program's stderr is the server's standard error, never the response, so a service with no console discards CGI warnings. Install only programs you trust, and only in the CGI directory. On a CGI route, `extensions=` restricts which programs may run, such as `extensions=cgi`: a program without a listed extension is refused even when the request path ends in one.
- **Keep the CGI environment and arguments safe.** Leave `ME_GOAHEAD_CGI_VAR_PREFIX` set (default `CGI_`), so request variables cannot overwrite the CGI environment. A query string with no `=` is passed to the program as command-line arguments, so do not put shells, interpreters or programs that take options or scripts from their arguments in the CGI directory.
- **Templates are never served as source.** The file handler refuses a `.jst` or `.asp` request with 404, so a template under a route that uses the file handler is not disclosed. To run templates there, add a `handler=jst` route with `extensions=jst,asp` for that prefix ahead of it.
- **Escape request data in templates, for the context it lands in.** `write` in a JavaScript template (`.jst`) outputs its arguments unchanged. Write anything that came from the request with `writeHtml`, or through `escape`, but only into HTML text or a quoted attribute value: always quote attributes, and never write request data into an unquoted attribute, a `<script>` outside a string, or a `<style>`. Inside a quoted JavaScript string, in a `<script>` block or a quoted `on*` attribute, use `escapeJs` instead, because `writeHtml` leaves the backslash intact and a browser decodes entities in an `on*` attribute before running it. `escapeUri` only encodes a value for a URL. It leaves `'`, `&` and a `javascript:` scheme intact, so its output must still go through `writeHtml` in a page, and a URL taken from the request must be checked against the schemes you allow.
- **Add security headers.** `ME_GOAHEAD_RESPONSE_HEADERS` adds headers to every response, one `Name: value` per line, such as `Content-Security-Policy: default-src 'self'`; it is empty by default. `X-Frame-Options: SAMEORIGIN` is sent by default (`ME_GOAHEAD_XFRAME_HEADER`). Other headers are yours to choose.
- **Leave stealth on.** `ME_GOAHEAD_STEALTH`, on by default, omits the `Server` header and refuses OPTIONS and TRACE requests.
- **Only static files are publicly cached.** Files served by the file handler with an extension in `ME_GOAHEAD_CLIENT_CACHE` are sent `Cache-Control: public` for anonymous GET and HEAD requests. Actions, templates, CGI, uploads and application handlers are sent `no-store, private` whatever their URL extension. An application handler whose output does not depend on the requester may set `WEBS_CACHEABLE` to allow public caching.
- **Keep staging directories out of the documents.** `ME_GOAHEAD_UPLOAD_DIR`, `ME_GOAHEAD_PUT_DIR` and `ME_GOAHEAD_TEMP_DIR` hold request data in transit. GoAhead refuses to start when one of them is inside a served directory, or when the temporary directory does not exist. `ME_GOAHEAD_TEMP_DIR` is `/tmp` by default, and on Windows it is empty, meaning the system temporary directory (`GetTempPath`, which honours `TMP` and `TEMP`), so keep both outside the documents. A client upload filename is checked as sent: one plain name, with no separator, leading or trailing dot or Windows device name. It is never a storage path, so do not save an upload under it without your own checks.

## Upgrading

- **Regenerate legacy password hashes.** Passwords created by releases before 6.2.0 are stored as legacy `BF1` hashes. They keep verifying, except those whose username and realm leave too little of the hash key for the password, which are refused and reported at startup. Regenerate every `BF1` password with `gopass`, which writes the current `BF2` format. Releases before 6.2.0 cannot verify a `BF2` hash.
- **Review the startup warnings.** After an upgrade, start once with `--verbose` and review any new warnings. Keep strict mode on: fix a route table the new release refuses rather than start it with `--no-strict`.
